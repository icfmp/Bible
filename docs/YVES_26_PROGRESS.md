# ZIP/YVES conversion and packaged SWORD proof — issue #26

Status: **installer implementation in draft PR #134; not merged or delivered in alpha**. This resumes the preserved work after the performance correction in signed alpha 40355737256-2. Numbered release #87 remains paused. No production profile, note, preference or downloaded translation is changed by these probes.

## Implemented and checked

The independent bounded adapter consumes edition JSON and its returned HTTPS offline URL, decodes YVES with strict UTF-8, and retains the original ordered tree and fragment references. ZIP handling checks every member before reading, rejects traversal, duplicates, links and encrypted entries, and enforces byte/count/depth/node limits. It never extracts archive paths into the filesystem. Unknown structures fail explicitly.

The semantic writer preserves paragraphs, poetry levels, section titles, additions, divine-name and Jesus-word markers, emphasis, foreign/transliterated words, quoted book titles, ordinal suffixes, list levels, embedded/no-break paragraphs, blank lines and footnote quotation/verse-number roles. Mappings follow the reviewed [USFM character](https://ubsicap.github.io/usfm/characters/index.html), [footnote](https://ubsicap.github.io/usfm/notes_basic/fnotes.html), [paragraph](https://ubsicap.github.io/usfm/paragraphs/index.html), [introduction](https://ubsicap.github.io/usfm/introductions/index.html) and [list](https://ubsicap.github.io/usfm/lists/index.html) definitions. It retains unknown data instead of silently flattening it or inventing wording/languages/list parents.

Explicit plus-joined verse units preserve each enumerated identifier with one text stream and one paired OSIS milestone. Missing verses are not manufactured. A verse can continue across a section heading without reopening/duplicating it. Notes in headings retain their body/printed locator and an actual following source anchor; note bodies never become Scripture text. Genuinely out-of-order units and unreviewed suffix/range syntax still fail.

Two independently reproduced SWORD 1.9.0 entity-fidelity defects need the small accompanying patch: OSISHeadings drops XML entities unless escape strings pass through, and osis2mod carries whitespace state across a text entity and drops the following separator. The package enables the standard SWORD utilities so `/app/bin/osis2mod` is available inside the same Flatpak as the bindings. No new application dependency is introduced; lxml is an isolated research oracle only.

## Complete-edition raw readback and source numbering

The private whole-edition probe compiles a combined, schema-valid OSIS document and independently checks all **1,189 chapters, 66 introductions, 31,112 units, 7,363 notes and 24 bridges** through SWORD. Text, note bodies/printed locators and title order match; no word/case/punctuation folding. Compilation is 1.39 seconds in this local environment; the conversion/build probe peaks near 203 MiB in its separate process. This is tooling consumption, not application startup RAM. No complete resource is registered by the probe.

The first full audit incorrectly required each native verse fragment to be an XML document. SWORD splits list/item markup across entries: eight chapters therefore produced fragment-parse errors, and the compiler reports 20 nesting warnings for those boundaries. The corrected oracle joins actual native entries in order, marks their boundaries with processing instructions and strictly parses the complete chapter, without a recovery parser. All body/annotation checks pass. Six introduction checks also exposed an oracle whitespace error around inline ordinal markup; concatenating inline text instead of inserting spaces resolves it. These changes do not suppress actual text or use the converter’s output as the DOM expectation; dedicated oracle tests cover them.

The returned `vrs=org` matches the [pinned SIL Original definition](https://github.com/sillsdev/libpalaso/blob/b4f7a6da7b868f9ae909e40fb0708f5fd4efd782/SIL.Scripture/Resources/org.vrs.txt), BHS OT / UBS GNT NT, at all 1,189 chapter maxima. The final installer registers **Original** as a separate native SWORD system, leaving German unchanged and eliminating its two extra index slots. German was only the earlier raw research storage system.

Reference-only SIL files, the MIT license and exact provenance are now included under `third_party/libpalaso`. `tools/versification/original.py --check` reproduces the compact Original mapping table. OT correspondence uses SIL English/Original rules after checking English OT bounds against KJVA. NT correspondence uses the already pinned JSword German UBS/GNT rules after checking every NT chapter bound against SIL Original. Unsupported source verse-part comments remain explicitly unmapped. Examples: Original Joel 4:1 → KJV Joel 3:1; Nehemiah 7:68 → KJV 7:68–69, 7:72 → 7:73; Psalm 3:9 → 3:8. An unnumbered Psalm heading is not silently assigned to a numbered target verse. Existing independent comparison fallback remains available.

## In-app implementation awaiting final packaged checks

- Library adds a YouVersion/Bible.com pilot entry for BDS 2015 (edition 21). Opening/refreshing the catalogue downloads metadata only. A resource download requires a local acknowledgement of the displayed source conditions. The source email-agreement requirement is shown explicitly; no agreement is submitted and no provider approval is claimed.
- Installation revalidates current metadata before acquiring content. Changed identity, requirements or returned URL require refreshing/reviewing the catalogue. Only the returned HTTPS host/path is accepted; redirects cannot change host or downgrade transport. Authentication refusals stop immediately. Transient refusal handling honours bounded Retry-After delays and remains cancellable.
- A URL-specific bounded cache retains completed archives and validated partial transfers. Resume uses Range/If-Range with a strong ETag; a complete matching archive is reused without a second ZIP request. No source text is included in the app or public artifacts.
- Conversion and complete native readback run in a separate Python process with the packaged compiler. Streaming chapter output bounds memory; cancellation terminates that process group and removes staging files. Conversion starts again from retained ZIP bytes on retry. Registration is atomic and occurs only after every source chapter/introduction, verse bridge, body, note and heading passes verification. Metadata, source hashes, parser version and numbering provenance are retained offline.
- Translation notes are a separate, read-only study tool. Only the visible chapter is parsed on demand; changing selected verses in that chapter reuses the view. Hidden tools perform no refresh and have no periodic source. Book introductions open from passage navigation without changing the reading passage or creating personal note references. Source inline italics/bold/small caps/superscripts are retained in ordinary and paginated documents.
- The first full local installer run used the actual retained BDS archive and exact source metadata, with network disabled by the test wrapper: **1,255 entries verified**, offline reopen and GTK editorial views passed. These figures exclude GUI startup and are not the client’s RAM measurement.
- The ordinary full local suite initially ran 346 tests with two obsolete fixed-count assertions (five sources / three tools). Those assertions are updated for the added source/tool; the rerun passed all **349 tests**. A further **48 affected French native/GTK tests** passed, including native Original boundaries/mapping and the local acknowledgement/download/retry UI. Later focused tests cover real conversion-process cancellation and milestone roles; the exact final installed package remains required. Do not confuse earlier green commits with these new installer changes.
