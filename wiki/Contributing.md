# Contributing and supporting Bible

**Bible is free and open source, and every helpful contribution matters.** You do not need to be a developer to make a difference. Testing the alpha, reporting a confusing interaction or improving a translation can be just as valuable as writing code.

## Test the alpha

The easiest way to help is to use Bible for ordinary reading and study.

1. [Install the Linux alpha](Installation).
2. Download a Bible translation from **Library** (`Ctrl+L`).
3. Try passage navigation, reading tabs, the study panel, notes and appearance settings.
4. If possible, test reading after disconnecting from the internet.
5. Report anything that breaks or feels unnecessarily complicated.

Bible is still in alpha: expect bugs and changing interfaces. Feedback from real reading sessions helps us prioritize the right improvements.

## Report a bug

Before opening an issue, search the [existing issues](https://github.com/icfmp/Bible/issues) to see whether the problem has already been reported.

If it is new, [open a bug report](https://github.com/icfmp/Bible/issues/new) with:

- **What happened** and **what you expected** instead.
- **Steps to reproduce** the problem, starting from a known state.
- **System details:** Linux distribution, desktop environment and version if known.
- **Installed Bible build:** run `flatpak info io.github.icfmp.Bible//alpha`.
- **Screenshots or error messages**, when helpful. Remove private notes, credentials and other personal information.

A short, reproducible report is often more useful than a long description without steps.

For installation and update problems, see [Troubleshooting](Troubleshooting).

## Suggest an improvement

We welcome ideas for improving Bible's reading and study experience. Start by explaining **the need**, not just a proposed interface or feature.

A useful suggestion answers three questions:

1. What are you trying to accomplish while reading or studying Scripture?
2. What makes that task difficult with Bible today?
3. How could the experience be improved **without adding unnecessary complexity**?

Check the [open issues](https://github.com/icfmp/Bible/issues) before creating a new proposal.

Not every suggestion will be implemented. We prioritize improvements that fit Bible's [project philosophy](Project-Philosophy): **Scripture first, simplicity over features**.

## Contribute code or interface translations

Code, testing, documentation and translations of **application interface text** are welcome.

Before starting:

1. Read [AGENTS.md](https://github.com/icfmp/Bible/blob/main/AGENTS.md) for the project's technical, product and contribution guidance.
2. Review the [open issues](https://github.com/icfmp/Bible/issues) and the current source code.
3. For substantial changes, discuss the intended user benefit and approach in an issue before investing significant effort.
4. Keep changes focused and include relevant tests or verification steps.

Bible is built with **Python, GTK 4, libadwaita and SWORD**. See the [README](https://github.com/icfmp/Bible#run-from-source) for development and test commands.

**A note about biblical texts:** helping translate the application's menus and messages is different from supplying a Bible translation or commentary. Scripture and study resources must respect the rights and distribution conditions of their respective publishers or authors. Please do not submit copyrighted texts without the necessary permission.

## Support Bible through Patreon

If Bible is useful to you and you would like to support its continued development, you can [support Bible on Patreon](https://www.patreon.com/BibleStudyApp).

**Financial support is entirely optional.** Bible remains free and open source, and its core functionality is not reserved for supporters.

Supporters may share feedback and feature requests through the channels offered on Patreon. Suggestions are still evaluated according to the same product principles as every other contribution; financial support does not guarantee that a particular feature will be implemented.

The best way to help is whichever suits you: **test, report, translate, contribute code, improve documentation or support financially.**

## Language and community

Please use **English** for public GitHub issues, pull requests, reviews, commit messages and contributor documentation. This makes discussions easier for contributors from different countries to follow.

The application itself supports **English and French**, and users can read installed resources in their available languages.

Keep feedback constructive and focused on helping readers. If a design decision is unclear, explain the task you are trying to perform and why the current experience falls short.
